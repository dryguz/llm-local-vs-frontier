How we estimate (and what we don't know)

  1. Quality [established, per benchmark]: Artificial Analysis Intelligence Index v5.0.2 plus four task-specific views built from its component evaluations: Coding (mean of FrontierCode-AA 2.0 and Terminal-Bench 4.1), Agentic workflows (AutomationBench-AA), Long documents (GDP.pdf) and Knowledge reliability without sources (AA-Omniscience net score: closed-book questions, it does not measure faithfulness to provided documents). Values were read from AA's charts on the date shown; models AA has not run on a benchmark are omitted from that view. On the hardest tasks (agentic coding, HLE) the gap is often wider than the average suggests. 4-bit quantization usually lowers quality somewhat versus the listed score.
  2. Generation [established mechanism]: each token requires reading the active weights once. Time/token ≈ Σ bytes from each memory tier / (bandwidth × 0.6) + overhead. MoE: the dense part always sits in the fastest memory, experts form a pool. A hot-expert cache holding fraction c of the pool serves 1−(1−c)skew of the accesses.
  3. Streaming from SSD [speculative]: missing experts are read from NVMe. Skew is calibrated on one measurement.
  4. Prompt processing [speculative]: 2 × active params × tokens / effective FLOPS. In SSD mode every prompt chunk touches nearly all experts, so the SSD-resident part is read once per chunk. Hardware FLOPS are estimates: replace them with your llama-bench pp512 result.
  5. Use cases [estimate]: each use case sets a token profile (input, answer, reasoning) and the most relevant quality metric. Token profiles are rough estimates; both can be changed under More settings. No AA benchmark measures faithfulness to provided sources directly, so for summarising tasks the closest proxy is GDP.pdf (long-document reasoning).
  6. Electricity [estimate]: whole-system power under load × time. Defaults are estimates from the TDP class; a wall meter is better. Hardware amortization and idle draw are not included.
  7. Currency [established rates]: all costs are computed in USD (API list prices) and converted with live ECB reference rates (NBP as fallback). The default electricity price is the 2026 Polish G11 average (1.04 PLN/kWh); set your own under More settings.
  8. API [established prices]: standard list prices, no caching, no batch (batch: −50% at Anthropic and OpenAI). Claude 4.7+ models use a tokenizer that yields ~30% more tokens for the same text; we apply a 1.3 multiplier.

Same model, different harness

A benchmark score belongs to a whole setup: model + harness (prompts, tool loop, context handling) + sampling settings + serving (provider, quantization). Artificial Analysis ran the same model through 13 coding-agent harnesses at maximum reasoning effort. The spread is comparable to the gap between neighbouring model tiers. Data exists for two models only, both on coding.

Metric: AA Coding Agent Index. Source: AA Coding Agents, Harness Comparisons, read 2026-11-25. Codex for GLM-5.3-Flash is marked with an asterisk on AA's chart.

What changes when you run a model yourself

  • Serving setup [unknown for AA scores]: AA does not state which provider, endpoint or quantization it uses for open-weights models.
  • Sampling [established that it matters, size unmeasured here]: AA uses temperature 0 for non-reasoning models and 0.6 for reasoning models unless the lab recommends otherwise; top-p and top-k are not stated. Local engines ship their own defaults. In agentic tasks one bad token (e.g. a malformed tool call) carries through all later steps, so the effect grows with task length.
  • Quantization and chat template [speculative size]: 4-bit weights and an incorrect chat template in the local engine can lower quality below the published score.
  • Harness [measured for coding]: see the chart above; a model can lose roughly a third of its score in a poorly matched harness.

None of this is modelled in the dashboard: local points use the published scores as-is, so treat them as an upper bound for a well-configured setup.
