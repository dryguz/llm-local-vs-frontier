How we estimate (and what we don't know)

  1. Quality [established, but a single metric]: Artificial Analysis Intelligence Index v5.0.2. One number from a test suite. On the hardest tasks (agentic coding, HLE) the gap is often wider than the average suggests. 4-bit quantization usually lowers quality somewhat versus the listed score.
  2. Generation [established mechanism]: each token requires reading the active weights once. Time/token ≈ Σ bytes from each memory tier / (bandwidth × 0.6) + overhead. MoE: the dense part always sits in the fastest memory, experts form a pool. A hot-expert cache holding fraction c of the pool serves 1−(1−c)skew of the accesses.
  3. Streaming from SSD [speculative]: missing experts are read from NVMe. Skew is calibrated on one measurement.
  4. Prompt processing [speculative]: 2 × active params × tokens / effective FLOPS. In SSD mode every prompt chunk touches nearly all experts, so the SSD-resident part is read once per chunk. Hardware FLOPS are estimates: replace them with your llama-bench pp512 result.
  5. Electricity [estimate]: whole-system power under load × time. Defaults are estimates from the TDP class; a wall meter is better. Hardware amortization and idle draw are not included.
  6. API [established prices]: standard list prices, no caching, no batch (batch: −50% at Anthropic and OpenAI). Claude 4.7+ models use a tokenizer that yields ~30% more tokens for the same text; we apply a 1.3 multiplier.
